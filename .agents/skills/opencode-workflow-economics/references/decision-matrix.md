# Delegation decision matrix

| Observed evidence | Usually favors |
|---|---|
| Frequent high-total-cost read-only pattern across many sessions | Candidate for semantic review as a cheap scout/research contract |
| Same structural pattern but semantically unrelated representative examples | Keep as an operational family; do not create one specialist |
| Child discovery followed directly by parent implementation/verification with no overlap | Evidence consistent with useful delegation |
| Exact child/parent path and query overlap before the parent's first write across many delegations | Investigate whether the child report is insufficient or duplicative |
| Exact overlap only after writes or during tests | Often verification; do not label it waste automatically |
| Missing child/parent timing or non-ordered overlap | Insufficient evidence for repeated-work labels; report unassigned exposure |
| Structural overlap without resource matches | Weak signal only |
| 1–3 known files and one local change | Main agent |
| Unknown symbols across layers, read-only mapping | Cheap scout |
| Broad documentation comparison with a compact output contract | Cheap research subagent |
| Repeated test/log triage with deterministic evidence | Specialist subagent |
| Architecture, tenancy, security, migrations | Strong main agent or strong specialist |
| Primary incomplete or blocked | Explicit stronger fallback |
| Large child report injected into expensive parent context | Compress or avoid delegation |
| Tiny low-cost task | Main agent |

This matrix is a prior, not a verdict. Use bundle evidence and distinguish measured facts from inference.
