# Paseo: abonament Claude i delegowanie do OpenCode/DeepSeek

## 1. Jaki to projekt i czy orkiestracja, MCP, API oraz pluginy są wydane?

### Takeaway
Oficjalny projekt to **getpaseo/paseo**, powiązany ze stroną **paseo.sh**. Paseo oferuje natywną orkiestrację między harnessami, a nie tylko wspólny panel niezależnych sesji: dokumentacja delegowania, MCP, pluginów i SDK znajduje się w opublikowanym tagu **v0.10.2**. [Repozytorium](https://github.com/getpaseo/paseo); [wydanie](https://github.com/getpaseo/paseo/releases/tag/v0.10.2); [orkiestracja w tagu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md).

### Cited Findings
- Identyfikacja: strona paseo.sh odsyła do getpaseo/paseo; README opisuje interfejs dla Claude Code, Codex, Copilot, OpenCode i Pi oraz lokalny daemon zarządzający agentami. To nie projekt sieci blockchain Paseo ani podobnie nazwane repozytoria. [Strona](https://paseo.sh); [README](https://github.com/getpaseo/paseo).
- Weryfikacja 30.09.2026: endpoint GitHub `releases/latest` zwrócił `v0.10.2`, `published_at: 2026-09-29T23:53:30Z`; treść release ma nagłówek „0.10.2 - 2026-09-30”. Podstawą stwierdzenia o wydaniu jest odpowiedź GitHub i zawartość tagu, nie sam bieżący dzień. [API wydania](https://api.github.com/repos/getpaseo/paseo/releases/latest); [release](https://github.com/getpaseo/paseo/releases/tag/v0.10.2).
- Oficjalna dokumentacja jawnie wymienia: uruchamianie agentów z dowolnym skonfigurowanym providerem/modelem, podział research/implementacja/review między providerami, wysyłanie promptów do agentów po ID, śledzenie postępu i zbieranie wyników. [Dokumentacja w tagu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md); [wersja WWW](https://paseo.sh/docs/orchestration).
- Wbudowane narzędzia tworzą relację rodzic–worker; worker pojawia się w „Subagents track”, a główny agent otrzymuje powiadomienie po zakończeniu pracy. Gdy `create_agent` nie dostanie `workspaceId`, subagent trafia do workspace rodzica; podanie innego workspace nie usuwa rodzicielstwa. [Orkiestracja](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md); [MCP](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md).
- **MCP / narzędzia natywne:** `daemon.mcp.enabled` ma domyślnie `true`, ale `daemon.mcp.injectIntoAgents` domyślnie `false`. Zależnie od providera narzędzia dostarczane są przez jego natywny interfejs lub MCP, z tymi samymi możliwościami. Po włączeniu trzeba rozpocząć lub przeładować sesję. [MCP w wydaniu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md).
- Katalog obejmuje `create_agent`, `send_agent_prompt`, `get_agent_status`, `get_agent_activity`, `list_agents`, `cancel_agent`, `kill_agent`, `update_agent`, `list_profiles`, `list_providers`, `list_models`, `inspect_provider`; ponadto workspace/worktree, terminale, harmonogramy i heartbeat. To API agent→agent, nie tylko ręczne przyciski UI. [Katalog MCP](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md).
- **CLI:** agent z dostępem do shella może użyć `paseo run --provider codex --background "Review this branch without changing files"`; wywołanie z agenta Paseo tworzy jego subagenta w tym samym workspace. Ta ścieżka nie wymaga włączenia injection MCP. CLI umożliwia też pracę z innym osiągalnym hostem. [Orkiestracja/CLI](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md).
- **Programistyczne API:** oficjalny SDK `@getpaseo/client` łączy się z daemonem przez WebSocket (`ws://127.0.0.1:6767/ws`), udostępnia `client.agents.create`, `agent.waitForFinish`, odnalezienie agenta po ID i kolejne prompty. `create` kończy się po powstaniu sesji; `waitForFinish` zwraca status i `lastMessage`. Nie trzeba pisać własnego SDK, choć napisanie odrębnego serwisu orkiestracji byłoby już pracą własną. [SDK quickstart w tagu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/sdk/quickstart.md).
- **Pluginy:** wydana dokumentacja opisuje TypeScript, entrypoint klienta i serwera, RPC daemona, rozszerzenia UI, slash commands, timeline i własnych providerów. Źródła instalacji: lokalny katalog, Git oraz npm. Nie jest to wyłącznie propozycja issue/roadmap. [Plugin quickstart w tagu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/plugins/index.md); [README](https://github.com/getpaseo/paseo).
- Oficjalne skills obejmują handoff, advisor i committee. README jako przykład handoff podaje planowanie z Claude i przekazanie implementacji do Codex. Skills uczą używania już istniejących narzędzi, nie są niezbędnym dodatkowym mostem. [README](https://github.com/getpaseo/paseo); [skills w wydaniu](https://github.com/getpaseo/paseo/tree/v0.10.2/skills).

### Inferences
- **Dla podstawowego Claude Code→OpenCode nie ma potrzeby budowania bespoke bridge.** Natywna warstwa Paseo zapewnia tworzenie, rodzicielstwo, komunikację i obserwację workerów; plugin lub własna aplikacja SDK są opcjami rozszerzeń, nie warunkiem delegowania. [Podstawa](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md).
- Potwierdzenie funkcji w tagu wydania jest mocniejsze od zapowiedzi marketingowej lub otwartego PR, ale nie dowodzi bezbłędnego działania każdej pary wersji runtime. [Tag/release](https://github.com/getpaseo/paseo/releases/tag/v0.10.2).

### Gaps
- Nie ustalano najwcześniejszych wersji, które wprowadziły poszczególne funkcje; potwierdzono ich dokumentację w `v0.10.2`. Nie sprawdzano lokalnej wersji użytkownika ani nie wykonywano testu end-to-end.
- Nie przedstawiono konkretnego planowanego, niewydanego feature jako dostępnego. Aktualne WWW może zmieniać się niezależnie od tagu; dlatego kluczowe twierdzenia oparto także na tagu wydania.

## 2. Czy Paseo uruchamia niezmodyfikowany Claude Code i zachowuje abonament?

### Takeaway
**Tak, według dokumentacji Paseo:** integracja korzysta z oficjalnego, już zainstalowanego `claude` przez Claude Agent SDK, z istniejącym kontem i limitami planu. Dokumentacja Anthropic dopuszcza logowanie użytkownika własnym abonamentem do niezmodyfikowanego Claude Code hostowanego przez platformę; nie należy utożsamiać tego z przenoszeniem tokena abonamentowego do własnego klienta API. [Paseo](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/claude-code.md); [Anthropic](https://code.claude.com/docs/en/legal-and-compliance).

### Cited Findings
- Paseo pisze dosłownie: „Paseo runs Claude Code through the official `claude` CLI using the Claude Agent SDK”, a użycie liczy się do normalnych limitów planu Claude i nie wymaga osobnej puli kredytów Agent SDK. Potrzebny jest plan zawierający Claude Code. [Claude Code w tagu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/claude-code.md).
- Użytkownik instaluje i loguje CLI na maszynie daemona; Paseo wykorzystuje tę instalację i konto. Po wygaśnięciu logowania ponowna autoryzacja CLI wymaga nowej sesji Paseo — istniejąca sesja zachowuje uwierzytelnienie z momentu uruchomienia. [Paseo Claude Code](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/claude-code.md).
- Kod providera importuje `@anthropic-ai/claude-agent-sdk`, ustawia `pathToClaudeCodeExecutable: claudeBinary`, preset `claude_code`, a `settingSources` na `user`, `project`, `local`. To potwierdza wykorzystywanie binarki Claude Code oraz ładowanie jej konfiguracji, nie implementację własnego klienta inferencji w miejsce Claude CLI. [Kod w tagu, szczególnie okolice linii 149 i 3290–3310](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/claude/agent.ts).
- Paseo pozwala też otworzyć terminal workspace i uruchomić zwykłe `claude` dla standardowego doświadczenia CLI. To odrębna forma interakcji od zarządzanej sesji providera i nie dowodzi automatycznego wstrzykiwania narzędzi Paseo do dowolnego procesu terminalowego. [Paseo Claude Code](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/claude-code.md).
- Anthropic w „Can customers offer Claude Code in their products?” wymaga niezmodyfikowanej binarki i własnych danych logowania każdego użytkownika; wymienia wprost abonament Claude jako jedną z dostępnych metod. W dalszej części zastrzega, że reguły dotyczące SDK i tokenów nie zabraniają użytkownikowi logowania własnym abonamentem do niezmodyfikowanej binarki, także hostowanej przez platformę. [Anthropic legal and compliance](https://code.claude.com/docs/en/legal-and-compliance).
- Równocześnie Anthropic odróżnia to od budowania własnego produktu/agentów SDK korzystających z logowania claude.ai lub limitów Pro/Max w imieniu klientów: dla takich zastosowań wskazuje API key/cloud provider. Sama obecność słowa „SDK” nie rozstrzyga przypadku; istotne jest, czy działa oryginalny Claude Code z własnym logowaniem użytkownika. [Anthropic legal and compliance](https://code.claude.com/docs/en/legal-and-compliance); [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview).
- Dokumentacja rozwiązywania problemów Anthropic wskazuje `ANTHROPIC_API_KEY` jako możliwą przyczynę używania rozliczeń API zamiast abonamentu; zaleca jego usunięcie z środowiska, gdy użytkownik chce używać subscription credentials. Nie badano środowiska lokalnego daemona. [Anthropic troubleshoot install](https://code.claude.com/docs/en/troubleshoot-install).

### Inferences
- Architektura **główny Claude Code/Opus na własnym abonamencie + worker OpenCode/DeepSeek na jego własnym backendzie** jest zgodna z udokumentowanym sposobem pracy Paseo. Opus musi być dostępny na danym koncie i w discovery modelów; Paseo nie zapewnia dodatkowego prawa dostępu ani zwiększonych limitów. [Paseo Claude](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/claude-code.md); [discovery i wybór modeli](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md).
- Nie ma potrzeby kierować abonamentowego Claude przez OpenCode ani kopiować OAuth do OpenCode. Claude pozostaje w swoim harnessie, a komunikacja z workerem odbywa się narzędziami Paseo. [Orkiestracja](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md); [Anthropic](https://code.claude.com/docs/en/legal-and-compliance).

### Gaps
- To potwierdzenie dokumentacji oraz implementacji, nie pomiar faktycznego billing użytkownika. Nie sprawdzano planu, dostępności konkretnego Opusa, środowiska `ANTHROPIC_API_KEY`, ani konfiguracji alternatywnych endpointów.
- Ogólna dokumentacja SDK zawiera ograniczenia dotyczące third-party login; nie znaleziono indywidualnego oświadczenia Anthropic zatwierdzającego markę Paseo. Konkretna podstawa hostowania pochodzi z sekcji o niezmodyfikowanym Claude Code, a konkretna deklaracja naliczania limitów — od Paseo. [Anthropic SDK](https://code.claude.com/docs/en/agent-sdk/overview); [Anthropic hostowanie](https://code.claude.com/docs/en/legal-and-compliance); [Paseo](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/claude-code.md).

## 3. Czy uruchomi dokładnie context-scout-fast/DeepSeek i jak rozumieć routing?

### Takeaway
Paseo potrafi uruchomić worker **OpenCode z wybranym modelem**, a Claude Code może delegować mu przez natywne narzędzia Paseo. Nie jest to jednak dowód automatycznego przeniesienia konkretnej definicji `context-scout-fast` z OpenCode do natywnego narzędzia subagentów Claude; istotne są typ roli OpenCode oraz dostępne tryby. [MCP](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md); [adapter OpenCode](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/opencode-agent.ts).

### Cited Findings
- Profil Paseo zapisuje provider, model, tryb, thinking i dostępne feature settings oraz notatki „When to use”. Orkiestrator odczytuje profile i wybiera ustawienia pasujące do zadania. [Agent profiles](https://paseo.sh/docs/agent-profiles).
- `create_agent` **nie ma parametru profile**; wymaga `provider/model`. Orkiestrator sam przekłada pola profilu na `provider`, `settings.modeId`, `settings.thinkingOptionId`, `settings.features`; zadanie przekazuje w `initialPrompt`. Gdy profilu nie wyposażono w model, powinien wywołać `list_models` i wybrać dostępny ID. [MCP w tagu](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md).
- Adapter OpenCode v1 odkrywa role przez `client.app.agents({ directory: cwd })`, mapuje nazwę roli na `modeId`, lecz `isSelectableOpenCodeAgent` dopuszcza tylko `mode: "primary"` lub `"all"` i odrzuca `hidden: true`. `mode: "subagent"` nie przechodzi tego filtra. [Kod: okolice 691–718 i 4909–4926](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/opencode-agent.ts).
- Przy wysyłaniu promptów/komend ten adapter przekazuje wybrany tryb jako pole OpenCode `agent: effectiveMode`. Gdy tryb nie został wskazany, pole jest pomijane, aby działał skonfigurowany default OpenCode. [Kod: okolice 642–651, 3660–3670, 3995–4010](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/opencode-agent.ts).
- Test E2E w wydaniu definiuje własnego agenta w `opencode.json` z `mode: "primary"` i sprawdza jego obecność w `availableModes`; nie jest to test automatycznego eksportowania roli subagent-only do Claude Code. Sam odczyt testu nie oznacza, że został uruchomiony podczas tego researchu. [Test discovery](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/daemon-e2e/opencode-custom-agents.real.e2e.test.ts).
- Adapter OpenCode v2 przy `session.create` przekazuje `agent: config.modeId ?? "build"` oraz wybrany model. Release `v0.10.2` zawiera kilka poprawek dotyczących OpenCode v2, więc dokładna wersja runtime ma znaczenie. [Adapter v2, okolice 107–116](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/opencode/v2/agent.ts); [release](https://github.com/getpaseo/paseo/releases/tag/v0.10.2).
- Paseo uruchamia istniejące, zainstalowane i uwierzytelnione CLI, zachowując ich subskrypcje/config/skills/MCP; wybór providera i modelu odbywa się na poziomie uruchamianej sesji. Dokumentacja SDK podaje OpenCode jako osobnego providera, np. `opencode/opencode/gpt-5.5`, z provider-native opcjami. [Providers](https://paseo.sh/docs/providers); [provider options](https://paseo.sh/docs/sdk/provider-options).

### Inferences
- **Praktyczna ścieżka bez własnego mostu:** zarządzana sesja Claude Code z dostępnym Opusem → włączone Paseo tools → discovery providerów/modeli/trybów → `create_agent` dla OpenCode z rzeczywistym ID modelu DeepSeek → prompt do researchu i odczyt wyniku/statusu. To połączenie harnessów przez Paseo, a nie podmiana backendu natywnego Claude subagenta. [MCP](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md); [orkiestracja](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md).
- Jeśli `context-scout-fast` jest selectable rolą `primary`/`all`, adapter v1 daje podstawę do wyboru jej jako trybu. Jeśli jest rolą wyłącznie `subagent`, nie należy obiecywać bezpośredniego wyboru jej z profilu Paseo; możliwa koncepcyjnie ścieżka to worker OpenCode delegujący wewnętrznie do tej roli, ale takiego przebiegu tutaj nie zweryfikowano. [Filtr selectable](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/opencode-agent.ts).
- **Routing zadań: tak. Wspólny proxy inferencji: nie wynika z zebranych źródeł.** Paseo umożliwia dobór harnessu/modelu dla workerów, lecz z tych dowodów nie wynika automatyczne kierowanie dowolnego pojedynczego wywołania Claude do DeepSeek ani wspólne rozliczenie dostawców. [Orkiestracja](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/orchestration.md); [Providers](https://paseo.sh/docs/providers).
- Dla celu użytkownika wystarcza udokumentowany mechanizm delegowania między sesjami z relacją rodzic–worker. Dokładne zachowanie istniejącej roli scouta pozostaje osobnym pytaniem konfiguracyjnym, nie brakiem ogólnej orkiestracji Paseo. [MCP parentage](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/mcp.md); [OpenCode discovery](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/agent/providers/opencode-agent.ts).

### Gaps
- Zgodnie z zakresem researchu nie czytano lokalnego repozytorium ani konfiguracji. Nie wiadomo, czy `context-scout-fast` ma `mode: subagent`, `primary` czy `all`, gdzie zdefiniowano jego model i jakie instrukcje/tools/permissions powinny zostać zachowane.
- Nie ustalono rzeczywistego ID DeepSeek wystawianego przez OpenCode użytkownika. Nazwa profilu ani skrót marketingowy modelu nie zastępują `list_models`.
- Nie potwierdzono identycznego discovery/filter zachowania w OpenCode v2; przeczytano jego tworzenie sesji, ale szczegółowa semantyka wyboru roli subagent-only wymaga osobnej weryfikacji.
- Nie testowano automatycznego powrotu dużych wyników, trwałości handoff po reconnect ani limitów/przycięcia kontekstu dla konkretnej pary Claude↔OpenCode. Potwierdzono oficjalną obietnicę powiadomienia o zakończeniu workera i narzędzia odczytu aktywności, nie konkretny limit długości przekazywanej treści.
