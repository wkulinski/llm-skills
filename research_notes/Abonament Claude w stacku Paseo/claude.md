# Claude Code z abonamentu i zewnętrzni workerzy MCP

Stan badania: 2026-09-30. Zakres: oficjalne granice autoryzacji Claude Code oraz gotowe mosty do workerów. Bez badania funkcji Paseo, pluginów providerów OpenCode, instalacji i lokalnego discovery. „Zweryfikowany projekt” oznacza odczyt jego źródłowej dokumentacji/artefaktów, nie wykonany przeze mnie test integracyjny. Oficjalne dokumenty sprawdzono również przez Context7 (`/websites/code_claude`).

## 1. Czy Opus z abonamentu może sterować zewnętrznymi workerami?

### Takeaway
Najlepiej udokumentowany wzorzec to własne logowanie do niezmodyfikowanego Claude Code, Opus jako koordynator oraz narzędzie MCP uruchamiające osobnego workera OpenCode. To delegowanie zadania do procesu/narzędzia, a nie dostarczenie DeepSeek jako natywnego modelu Claude Code. Oficjalne wsparcie dotyczy mechanizmu MCP i sposobu uruchamiania Claude Code, nie jakości lub zatwierdzenia konkretnego mostu społecznościowego. — [MCP](https://code.claude.com/docs/en/mcp); [polityka](https://code.claude.com/docs/en/legal-and-compliance)

### Cited Findings
- Anthropic jawnie dopuszcza uruchamianie Claude Code przez platformę, także w hostowanych sandboxach/infrastrukturze agentowej, pod warunkami: **niezmodyfikowany binary**, bez usuwania/ograniczania metod autoryzacji, własne dane logowania każdego użytkownika, bez opłacania/odsprzedawania/pośredniczenia w użyciu na jego rzecz. Oferowanie tego w produkcie/usłudze wymaga Commercial Terms. — [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- OAuth abonamentów Free/Pro/Max/Team/Enterprise służy zwykłemu użyciu Claude Code i natywnych aplikacji Anthropic. Developerzy nie mogą oferować własnego logowania Claude.ai ani zbierać, przechowywać czy pośredniczyć w poświadczeniach/session tokens. Polityka wyraźnie zachowuje możliwość logowania użytkownika do niezmodyfikowanego Claude Code przez flow Anthropic. — [Authentication and credential use](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)
- Claude Code oficjalnie obsługuje lokalne serwery MCP stdio oraz zdalne HTTP, także z nagłówkiem Bearer. MCP może udostępniać narzędzia, bazy i API. Bearer własnego workera MCP nie jest tokenem OAuth Claude.ai i nie zmienia dostawcy głównego modelu. — [MCP](https://code.claude.com/docs/en/mcp)
- **Ważny niuans gateway:** obecna dokumentacja opisuje techniczne działanie abonamentu przy samym `ANTHROPIC_BASE_URL`, bez credential gatewaya: zapisany login pozostaje aktywny. Dodanie `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` lub `apiKeyHelper` zastępuje login i ruch rozliczany jest według credential upstreamu. Nie należy twierdzić, że każdy proxy technicznie wyłącza abonament; dokumentacja tego mechanizmu nie daje jednak zgody na zbieranie/intermediację tokenów w produkcie trzecim. — [Subscriptions and gateways](https://code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways); [polityka](https://code.claude.com/docs/en/legal-and-compliance)
- Anthropic wprost **nie wspiera routingu Claude Code do modeli nie-Claude przez gateway**. Dlatego gateway kierujący część wywołań do DeepSeek nie jest oficjalnie wspieraną odpowiedzią na wymaganie „Opus abonament + tani worker”. — [Other LLM gateways](https://code.claude.com/docs/en/llm-gateway)
- Agent SDK uruchamia binary Claude Code jako bibliotekę. Overview nakazuje API-key authentication developerom produktów bez wcześniejszej zgody na logowanie/rate limits Claude.ai. Jednocześnie legal page mówi, że reklamowane limity Pro/Max zakładają ordinary individual usage Claude Code **i Agent SDK**, a env reference opisuje `CLAUDE_CODE_OAUTH_TOKEN` w SDK/automatyzacji. To nie jest ani dowód całkowitego zakazu osobistego SDK, ani blanket permission na abonament w dowolnym zewnętrznym orchestratorze. — [SDK overview](https://platform.claude.com/docs/en/agent-sdk/overview); [Legal](https://code.claude.com/docs/en/legal-and-compliance); [Env vars](https://code.claude.com/docs/en/env-vars)

### Inferences
- Preferowany układ: `Claude Code / Opus / własny abonament → MCP worker bridge → OpenCode / własny DeepSeek`. Claude nie oddaje swoich tokenów mostowi; OpenCode sam rozwiązuje model i swoje poświadczenia. Jest zgodny z udokumentowanym rozdzieleniem narzędzia i autoryzacji, lecz nie oznacza certyfikacji mostu przez Anthropic. — [MCP](https://code.claude.com/docs/en/mcp); [Legal](https://code.claude.com/docs/en/legal-and-compliance)
- Nie ma potrzeby budować własnego Agent SDK orchestratora tylko po to, by zachować Opus z abonamentu: gotowy launcher MCP może działać pod zwykłym Claude Code. — [MCP](https://code.claude.com/docs/en/mcp); [ai-cli-mcp](https://github.com/mkXultra/ai-cli-mcp)

### Gaps
- Nie znamy planu użytkownika ani jego aktualnego przydziału Opus; wybór `opus` nie gwarantuje entitlement konkretnego konta. Dostępność i limity należy potwierdzić w zalogowanym Claude Code. — [Model configuration](https://code.claude.com/docs/en/model-config)
- Nie uzyskano indywidualnej interpretacji Anthropic dla konkretnej platformy/mostu; nie zastępuję warunków i ewentualnej zgody producenta deklaracją projektu społecznościowego. — [Legal](https://code.claude.com/docs/en/legal-and-compliance)

## 2. Co naprawdę umożliwiają natywne subagenty i `claude mcp serve`?

### Takeaway
Natywny agent może mieć alias lub **pełny model ID**, ale sam ID nie tworzy providera ani niezależnego endpointu. `claude mcp serve` jest oficjalnym serwerem **narzędzi**, nie udokumentowaną usługą „zapytaj Opus z abonamentu”. — [Subagents](https://code.claude.com/docs/en/sub-agents#choose-a-model); [Model config](https://code.claude.com/docs/en/model-config); [MCP server](https://code.claude.com/docs/en/mcp#use-claude-code-as-an-mcp-server)

### Cited Findings
- `model` subagenta przyjmuje alias, pełny model ID (takie same wartości jak `--model`) lub `inherit`. Twierdzenie „tylko opus/sonnet/haiku, pełne ID zabronione” jest nieaktualne. Subagenty wysyłają osobne requesty liczone do wspólnych limitów głównej sesji. — [Choose a model](https://code.claude.com/docs/en/sub-agents#choose-a-model); [Subagents](https://code.claude.com/docs/en/sub-agents)
- Model configuration rozróżnia nazwy Anthropic API, profile ARN Bedrock, deployment Foundry i wersje Google. `ANTHROPIC_BASE_URL` zmienia miejsce wysyłania requestów, nie model, który odpowiada. — [Available models](https://code.claude.com/docs/en/model-config#available-models)
- Oficjalny frontmatter subagenta dokumentuje m.in. `model`, `tools`, `mcpServers`, permissions i isolation; nie przedstawia osobnej konfiguracji `provider`, `baseURL` i credential per subagent. Endpointy providerów są opisane jako konfiguracja sesji/procesu, np. `ANTHROPIC_BASE_URL` i `ANTHROPIC_VERTEX_BASE_URL`. Brak dokumentowanego kontraktu „główna sesja abonamentowa, natywny agent DeepSeek na własnym endpointcie”. — [Frontmatter reference](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields); [Gateway connection](https://code.claude.com/docs/en/llm-gateway-connect)
- Oficjalna komenda `claude mcp serve` działa po stdio i **only exposes Claude Code’s tools**. Klient odpowiada za potwierdzanie tool calls. Nie jest obietnicą udostępnienia agent loop ani inference Opus. — [Use Claude Code as an MCP server](https://code.claude.com/docs/en/mcp#use-claude-code-as-an-mcp-server)
- Do sterowania pełną pętlą agenta z innego procesu oficjalne SDK overview wskazuje też CLI subprocess z `-p --output-format json`; to inna powierzchnia niż `mcp serve`. — [Agent SDK overview](https://platform.claude.com/docs/en/agent-sdk/overview)

### Inferences
- Dla taniego scouta potrzebne jest narzędzie MCP, które uruchamia **zewnętrzny** agent loop OpenCode, nie `model: deepseek/...` w natywnym subagencie Claude. Można otoczyć narzędzie dedykowanym subagentem Claude, ale ten wrapper również zużywa limit abonamentu. — [Subagents](https://code.claude.com/docs/en/sub-agents); [ai-cli-mcp](https://github.com/mkXultra/ai-cli-mcp)
- W kierunku odwrotnym, `OpenCode → MCP → Claude Code`, należy wybrać launcher pełnego CLI, a nie zakładać, że oficjalne `mcp serve` zwróci reasoning Opus. — [MCP server](https://code.claude.com/docs/en/mcp#use-claude-code-as-an-mcp-server); [ai-cli-mcp](https://github.com/mkXultra/ai-cli-mcp)

### Gaps
- Brak zweryfikowanego oficjalnego mechanizmu niezależnych endpointów/providers dla natywnych subagentów w jednej sesji abonamentowej. To wniosek z udokumentowanych kontraktów, nie analiza wszystkich ścieżek wewnętrznego kodu Claude Code. — [Subagents](https://code.claude.com/docs/en/sub-agents); [Gateway docs](https://code.claude.com/docs/en/llm-gateway)

## 3. Które gotowe projekty pasują do tego stacku?

### Takeaway
Pierwszy wybór do lokalnego pilota to **mkXultra/ai-cli-mcp**: rzeczywisty pakiet MCP, uruchamia zarówno OpenCode, jak i Claude CLI. Jeśli najważniejsze jest jawne wskazanie istniejącego agenta `context-scout-fast`, najlepiej udokumentowaną powierzchnię ma **ManuOtel/opencode-mcp-bridge**, lecz wymaga self-hostingu i sam oznacza integrację Claude Code jako end-to-end unverified. — [ai-cli-mcp](https://github.com/mkXultra/ai-cli-mcp); [Worker API](https://github.com/ManuOtel/opencode-mcp-bridge/blob/master/docs/tool-api.md); [Compatibility](https://github.com/ManuOtel/opencode-mcp-bridge/blob/master/docs/compatibility.md)

### Cited Findings

Ranking dopasowania do wymagań, nie ranking popularności ani gwarancja niezawodności:

| Miejsce / projekt | Potwierdzona powierzchnia | Dopasowanie i blokery |
|---|---|---|
| **1. [mkXultra/ai-cli-mcp](https://github.com/mkXultra/ai-cli-mcp)** | MCP stdio, background jobs, `run`, wait/result/peek/kill, CLI Claude i OpenCode; OpenCode: `opencode run --format json --dir ...`; `opencode` = default, `oc-<provider/model>` = jawny model. [package.json](https://github.com/mkXultra/ai-cli-mcp/blob/main/package.json) potwierdza entrypointy MCP/CLI, wersję 3.1.0 i zależność `cross-spawn`, bez Agent SDK jako zależności runtime. | Najmniej dodatkowej infrastruktury; może pracować w obie strony. [clink docs](https://github.com/BeehiveInnovations/pal-mcp-server/blob/main/docs/tools/clink.md) | Gotowy, gdy zaakceptujesz innego CLI workera lub bezpośredni API worker. **Nie potwierdzono gotowego adaptera OpenCode**: dodanie CLI może wymagać parsera/agent implementation, nie tylko JSON. `chat/consensus` używają provider API, a `clink` uruchamia CLI — tych trybów nie wolno utożsamiać. Nie polecam też ścieżki rotation kont jako odpowiedzi na wymaganie pojedynczego abonamentu. — [README](https://github.com/ralphkrauss/agent-orchestrator/blob/main/README.md)

### Inferences
- **Opcja A — najprostszy pilot:** standardowy Claude Code `--model opus` z własnym loginem + MCP `ai-cli-mcp` + worker `opencode` lub jawny `oc-<rzeczywisty-provider/model>`. To nie wymaga bespoke bridge. Brak pewnego wyboru nazwanego agenta pozostaje blokerem, jeśli musi być dokładnie `context-scout-fast`, a nie równoważny prompt scouta na tym samym modelu. — [Model config](https://code.claude.com/docs/en/model-config); [ai-cli-mcp](https://github.com/mkXultra/ai-cli-mcp)
- **Opcja B — istniejący scout jako kontrakt:** Claude Code + ManuOtel bridge; planowany call `worker_run(agent="context-scout-fast", providerID="<ID z konfiguracji>", modelID="<ID z konfiguracji>", directory="<repo workera>", message="<bounded scout task>")`, potem `worker_wait`/`worker_verify`. To przykład zgodny ze schematem narzędzia, nie potwierdzony live run; nazwa agenta i provider/model muszą istnieć w konfiguracji serwera OpenCode. — [Tool API](https://github.com/ManuOtel/opencode-mcp-bridge/blob/master/docs/tool-api.md)
- **Opcja C — bogatszy lokalny lifecycle:** coder-mcp-bridge, jeśli priorytetem są guide/interrupt/recover i brak HTTP deploymentu bridge'a. Najpierw potrzebny dowód wyboru agenta/modelu i zgodności wersji OpenCode. — [README](https://github.com/Deslord319/coder-mcp-bridge/blob/main/README.en.md)
- Przykład rejestracji stdio do przyszłego pilota, **nie wykonano**: `claude mcp add --transport stdio ai-cli -- npx -y ai-cli-mcp@<zweryfikowana-wersja>`. Składnia oparta na oficjalnym `mcp add`, zamiast przepisywania niejednoznacznego przykładu JSON z README projektu. Wersja 3.1.0 jest potwierdzona w source package.json; nie sprawdzono jej dostępności w registry npm. — [Official MCP](https://code.claude.com/docs/en/mcp); [package.json](https://github.com/mkXultra/ai-cli-mcp/blob/main/package.json)

### Gaps
- Nie wykonano instalacji, testów ani logowania; dla wszystkich rekomendacji trzeba osobno potwierdzić rzeczywiste połączenie Claude Code → tools/list → worker → wynik. Zweryfikowano istnienie i udokumentowane kontrakty projektów, nie działanie konkretnego stacku użytkownika.
- Nie odczytano lokalnej konfiguracji `context-scout-fast`, dlatego brak rzeczywistych provider/model ID oraz dowodu, że worker w nowym procesie/na serwerze załaduje ten sam scope konfiguracji.
- Nie zbadano integracji Paseo ani pluginów providerów OpenCode zgodnie z przydziałem. Wynik nie przesądza, jak UI Paseo pokaże status lub approval zewnętrznego workera.
- Materiały upstream są ruchome. Wdrożenie powinno przypiąć release/commit; numery wersji i przykłady z README nie są dowodem vendor approval ani uprawnienia do abonamentowego inference poza standardowym Claude Code. — [Legal](https://code.claude.com/docs/en/legal-and-compliance); [ManuOtel compatibility](https://github.com/ManuOtel/opencode-mcp-bridge/blob/master/docs/compatibility.md)
